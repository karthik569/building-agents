Exit when a turn contains no tool calls, or when you hit the step cap. 

messages = [system, user_task]
for step in range(MAX_STEPS):
    turn = model(messages, tools)
    messages.append(turn)
    if not turn.tool_calls:
        return turn.text          # done
    for call in turn.tool_calls:
        result = run(tool=call.name, **call.args)
        messages.append({"tool", call.id, result})
return TIMEOUT                    # never omit this branch

What each piece is actually for

Context list
The entire memory. The provider is stateless — it sees only what you resend. Append-only is the simplest correct model. Not a cache. Not a database. A list you rebuild each call.
Tool calls
Structured output, parsed into a name plus arguments. The model is not executing anything; it is asking you to. Not actions. Not side effects. Requests.
Tool results
Plain content appended with a matching id. Errors are results too. Not exceptions. Never raise into the loop.
Step cap
The only thing standing between a confused model and an unbounded bill. Not a timeout. A budget on reasoning steps.
Trace
Every event as data: step, kind, detail. Built so a failed run can be replayed. Not print statements. Not a log file.

Compound error — the arithmetic that governs everything

Per-step accuracy is not task accuracy

95% per step over 10 steps ≈ 60% success. Over 100 steps ≈ 0.6%.

This is why step caps and short agents beat clever planners.

Consequences

  • Prefer fewer, coarser steps.
  • Make each step verifiable (tests, schemas).
  • Return errors as content so step N+1 can repair step N.

Failure modes to check in this order

Invalid tool
Model names a tool that is not in the inventory. Cause: stale prompt, or tool names that are too similar to each other.
Invalid parameters
Right tool, wrong shape. Cause: schema too permissive, or missing required fields. Fix the shape, not the prompt.
Wrong parameter values
Right shape, wrong content — a path, an ID, a date. Cause: the model guessed instead of reading. Fix by requiring a read step first.
Tool failure
The tool ran and returned garbage. Your bug, not the model's. Add a test at the tool boundary.
Reflection failure
The agent insists it succeeded when it did not. Cause: no ground truth in the loop. Fix with an executable check, not more prompting.
Loop / thrash
Repeating a call that already failed. Cause: error content too vague, or no memory of the attempt. Fix the error message; it is prompt text.

Sentences to use in a design review

Defensible

  • "The steps are known, so this is a workflow."
  • "We cap at six steps; median is three."
  • "Errors return as content so it can self-correct."
  • "The path is absolute because relative paths broke us."
  • "The eval set is 20 tasks; we gate merges on it."

Red flags

  • "The framework handles that."
  • "It works when I try it."
  • "We added another agent to check the first agent."
  • "The prompt is 4,000 lines but it's fine."
  • "We'll add evals after launch."
